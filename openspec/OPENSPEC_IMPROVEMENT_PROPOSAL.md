# OpenSpec 改进提案

## 背景

在实现 `add-external-image-replacement` 功能时，发现以下问题：

1. **任务完成但实现有误**：`Copy()` 使用方式错误，导致功能失败
2. **集成测试被标记为可选**：关键测试被跳过，bug 未被发现
3. **应用层逻辑遗漏**：开关控制逻辑完全缺失，导致功能耦合

这些问题说明当前 OpenSpec 流程在以下方面需要加强：
- 任务验收标准
- 测试策略
- 实现完整性检查

## 改进建议

### 1. 任务定义增强

#### 当前格式
```markdown
- [ ] 2.3 如果回调返回替换图片，调用 `external_image->Clone(nullptr)` 创建内部副本
```

#### 改进格式
```markdown
- [ ] 2.3 创建替换图片的内部副本
  - **实现**：调用 `internal_copy->Copy(replacement)` 创建独立副本
  - **验收**：
    - [ ] `Copy()` 调用返回 `true`
    - [ ] 日志显示 "Created internal copy" 消息
    - [ ] 内存地址与外部图片不同
  - **测试**：使用不同尺寸的替换图片验证功能
```

**要点**：
- 明确实现方法
- 定义可验证的验收标准
- 包含具体的测试场景

### 2. 测试策略强化

#### 当前问题
```markdown
- [ ] 5.5 编写单元测试验证图片替换逻辑和 Clone 操作（可选）
- [ ] 5.6 测试 AP-Form 场景下的实际替换（需要应用层实现）
```

**问题**：
- "可选" 导致跳过
- "需要应用层实现" 变成手工任务

#### 改进方案

**禁止使用"可选"标记**：
- 如果真的可选，就不要写入 tasks.md
- 如果需要，就标记为必需并完成

**新的测试分级**：

```markdown
## 测试任务

### 单元测试（必需）
- [ ] 5.1 测试 `GetReplacementImage()` 返回值处理
  - [ ] 返回 `nullptr` 时使用原图
  - [ ] 返回替换图片时创建内部副本
  - [ ] `Copy()` 失败时回退到原图

### 集成测试（必需）
- [ ] 5.2 端到端测试图片替换流程
  - [ ] 加载测试 PDF（包含 AP-Form 图片）
  - [ ] 设置替换图片
  - [ ] 验证渲染结果（通过日志或输出文件）
  - [ ] 验证水印可以叠加到替换后的图片

### 回归测试（必需）
- [ ] 5.3 验证现有功能不受影响
  - [ ] 未设置替换时显示原图
  - [ ] 水印功能独立工作
  - [ ] 非 AP-Form 图片不受影响
```

### 4. 实施 "验收驱动开发"（Acceptance-Driven Development）

#### 流程改进

**当前流程**：
```
1. 读 proposal.md
2. 读 design.md
3. 读 tasks.md
4. 逐个实现任务
5. 标记完成
```

**改进流程**：
```
1. 读 proposal.md 理解目标
2. 读 design.md 理解设计
3. 读 tasks.md 并为每个任务写验收测试
4. 实现任务
5. 运行验收测试
6. 测试通过 → 标记完成
7. 所有任务完成后运行集成测试
8. 集成测试通过 → 更新状态
```

#### 验收测试示例

对于任务：
```markdown
- [ ] 2.3 创建替换图片的内部副本
```

验收测试（伪代码）：
```cpp
TEST(ImageReplacement, CreateInternalCopy) {
  // 准备
  auto replacement = CreateTestBitmap(100, 100);
  auto callback = new TestCallback(replacement);
  
  // 执行
  auto result = RenderWithCallback(callback);
  
  // 验证
  ASSERT_TRUE(result != nullptr);
  ASSERT_EQ(result->GetWidth(), 100);
  ASSERT_NE(result.Get(), replacement.Get());  // 不同地址
  
  // 日志验证
  ASSERT_LOG_CONTAINS("Created internal copy");
}
```

### 6. AI Agent 指令增强

在 `openspec/AGENTS.md` 中添加：

```markdown

### 任务验收标准

**每个任务必须满足**：
1. ✅ 代码已编写
2. ✅ 编译通过（无错误，警告已处理）
3. ✅ 验收条件已满足（如定义）
4. ✅ 相关日志已验证
5. ✅ 相关文档已更新

**禁止操作**：
- ❌ 将关键测试标记为"可选"
- ❌ 在未验证功能的情况下标记完成
- ❌ 将应用层集成留给用户手工实现

### 验证清单

在标记任务完成前，必须：

```bash
# 1. 编译验证
./build_script.sh  # 必须通过

# 2. 日志验证（如适用）
grep "Expected log message" debug.log  # 必须找到

# 3. 功能验证（如适用）
# 运行应用并触发功能，检查行为是否符合预期

# 4. 回归验证
# 确认现有功能未受影响
```

### 遇到问题时

如果实现过程中发现：
- API 使用不正确 → 立即修正，更新 design.md
- 需要额外的开关/配置 → 更新 design.md 和 tasks.md
- 用户体验问题 → 咨询用户或提出建议

**不要**：
- 不要假设问题会在后续阶段被发现
- 不要跳过验证直接标记完成
- 不要留下"TODO"或"FIXME"标记
```
