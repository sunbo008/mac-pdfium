# 任务模板（带验收标准）

## 任务格式规范

### ❌ 不好的任务定义

```markdown
- [ ] 1.1 实现图片替换功能
- [ ] 1.2 添加错误处理
- [ ] 1.3 更新文档（可选）
```

**问题**：
- 太宽泛，不知道"实现"到什么程度
- "错误处理"范围不明确
- "可选"会被跳过

### ✅ 好的任务定义

```markdown
## 1. 核心功能实现

- [ ] 1.1 在 `ImageRenderer` 中添加图片替换调用点
  - **位置**：`StartRenderDIBBase()` 方法，在获取 bitmap 后
  - **实现**：调用 `callback->GetReplacementImage()`
  - **验收**：
    - [ ] 编译通过
    - [ ] 日志显示 "Got replacement image" 当返回非 null
    - [ ] 日志显示 "No replacement" 当返回 null
  - **测试**：使用 mock callback 返回不同值

- [ ] 1.2 创建替换图片的内部副本
  - **位置**：`StartRenderDIBBase()` 方法
  - **实现**：`internal_copy->Copy(replacement)`
  - **验收**：
    - [ ] `Copy()` 返回 `true`
    - [ ] 日志显示内存地址（`LOG_INFO_F("Created at %p", ptr)`）
    - [ ] 失败时回退到原图并记录警告
  - **测试**：
    - 正常尺寸图片 (640x480)
    - 极端尺寸图片 (1x1, 10000x10000)
    - null 输入

- [ ] 1.3 错误处理：`Copy()` 失败时的回退逻辑
  - **触发条件**：`Copy()` 返回 `false`
  - **预期行为**：
    - 记录 WARNING 日志
    - 继续使用原始 bitmap
    - 不应崩溃或泄漏内存
  - **验收**：
    - [ ] 日志包含 "Failed to copy replacement image"
    - [ ] `dibbase_` 指向原始 bitmap
    - [ ] 渲染继续正常进行
  - **测试**：模拟 `Copy()` 失败场景
```

## 测试任务模板

```markdown
## 5. 测试验证

### 单元测试（必需）

- [ ] 5.1 测试 `GetReplacementImage()` 的不同返回值
  - **场景**：
    - 返回 `nullptr`（不替换）
    - 返回有效 bitmap（替换）
    - 返回格式不兼容的 bitmap
  - **验收**：所有场景渲染正常，无崩溃
  - **方法**：创建测试 PDF，使用 mock callback

- [ ] 5.2 测试内部副本创建
  - **验证点**：
    - 替换图片与内部副本内存地址不同
    - 外部释放替换图片后内部副本仍有效
    - 不同尺寸替换图片都能正确复制
  - **验收**：通过内存检查工具（如 valgrind）
  - **方法**：单元测试 + 内存检查

### 集成测试（必需）

- [ ] 5.3 端到端测试：真实 PDF + 真实图片
  - **输入**：
    - 包含 AP-Form 的测试 PDF
    - 不同格式的替换图片（PNG, JPEG）
  - **操作**：
    1. 打开 PDF
    2. 设置替换图片
    3. 渲染页面
    4. 检查输出或日志
  - **验收**：
    - [ ] 日志显示完整替换流程
    - [ ] 渲染耗时在合理范围（<200ms）
    - [ ] 输出图片包含替换内容
  - **方法**：手动测试 + 日志验证

- [ ] 5.4 测试与水印功能的配合
  - **场景**：
    - 只启用替换（显示替换图片）
    - 只启用水印（原图 + 水印）
    - 同时启用（替换图片 + 水印）
    - 都不启用（原图）
  - **验收**：4 种场景输出都符合预期
  - **方法**：手动测试，对比输出

### 回归测试（必需）

- [ ] 5.5 验证现有功能不受影响
  - **测试项**：
    - [ ] 普通图片渲染（非 AP-Form）
    - [ ] 水印独立功能
    - [ ] PDF 加载/关闭流程
  - **验收**：所有功能与之前行为一致
  - **方法**：手动测试对比
```

## 使用指南

### 创建任务时

1. **具体化**：每个任务只做一件事
2. **可验证**：明确验收标准
3. **可测试**：说明如何测试
4. **有价值**：解释为什么需要这个任务

### 实施任务时

1. **先写验收测试**（如适用）
2. **实现功能**
3. **运行测试**
4. **验证日志**
5. **标记完成**

### 标记完成前

必须满足所有验收条件，不能"差不多就行"。

如果验收条件不合理，应该：
1. 停止实施
2. 更新 tasks.md 和 design.md
3. 重新评估
4. 继续实施

## 反面教材：本次 bug 案例

### 原任务定义
```markdown
- [X] 2.3 如果回调返回替换图片，调用 `external_image->Clone(nullptr)` 创建内部副本
```

### 问题分析
- ❌ 没有验收标准（如何知道"创建成功"？）
- ❌ 没有测试方法（如何验证？）
- ❌ API 使用错误（`Create() + Copy()` vs 直接 `Copy()`）
- ❌ 标记完成但未实际验证

### 改进后的任务
```markdown
- [ ] 2.3 创建替换图片的内部副本，避免依赖外部内存
  - **背景**：外部提供的 bitmap 可能是临时的，需要内部持有副本
  - **实现**：`internal_copy->Copy(replacement)`（注意：Copy 内部会 Create）
  - **验收**：
    - [ ] `Copy()` 返回 `true`
    - [ ] 日志显示 "Created internal copy at 0x..." 和尺寸
    - [ ] 失败时记录 WARNING 并使用原图
    - [ ] 替换图片和内部副本内存地址不同
  - **测试**：
    - 正常图片替换：验证地址不同
    - `Copy()` 失败：验证回退到原图
    - 外部提前释放：验证内部副本仍可用
  - **注意**：不要先调用 `Create()`，`Copy()` 会自动处理
```

这样定义的任务：
- ✅ 实现方法明确
- ✅ 验收标准可验证
- ✅ 包含测试方法
- ✅ 包含常见陷阱提示
